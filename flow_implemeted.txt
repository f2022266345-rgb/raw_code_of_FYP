LUMINA Cognitive Understanding Flow (Implemented)

This document explains, in detail, how observable student interaction logs are converted into latent cognitive states.

====================================================================
1) WHAT WAS IMPLEMENTED
====================================================================

A. BKT Engine (per skill, P(Know))
- Knowledge component source:
  - skill_id/skillName/contentId from interaction metadata/content context.
- For each interaction that contains correctness evidence:
  - Find user skill row in bkt_skill_mastery using skill identifier.
  - Apply Bayesian Knowledge Tracing update.
  - Increment practice count.
  - Update last practiced timestamp.

B. Trend Engine (last N interactions)
- Window size N is constrained to 5..10 (default 8).
- For each user, regression slope is computed over latest N student_interactions:
  - accuracy trend slope
  - response-time trend slope
  - hint trend slope

C. Hidden State Store (student_profile_state)
- A dedicated table stores latent state snapshot:
  - mastery_summary
  - accuracy_trend_slope
  - time_trend_slope
  - hint_trend_slope
  - frustration_estimate
  - engagement_estimate
  - readiness_estimate
  - hidden_state (full mapping JSON)
  - interaction_window
  - last_computed_at

====================================================================
2) TABLES INVOLVED
====================================================================

1. interaction_logs
- Raw event stream used by existing dashboards/APIs.

2. student_interactions
- Research-ready, structured interaction table for cognitive analysis.
- Stores correctness, hints, attempts, response time, content id, agent type,
  message text, sentiment, session time.

3. bkt_skill_mastery
- Per user, per skill mastery probability P(Know).

4. student_profile_state
- Latent cognitive state snapshot computed from recent observables + BKT summary.

====================================================================
3) END-TO-END PIPELINE
====================================================================

Step 1: Interaction arrives
- Sources:
  - /api/observations/log
  - /api/observations/batch
  - /api/observations/hint
  - Chat events persisted by /api/chat

Step 2: Normalize and persist observables
- Event is normalized in observations/chat controller.
- Persisted to interaction_logs.
- Also mapped/persisted to student_interactions.

Step 3: BKT update trigger
- For each new student_interaction:
  - If correctness is present and skill identifier exists:
    - Locate BKT skill row.
    - Apply BKT Bayesian update formula.
    - Save new p_mastery.

Step 4: Trend extraction (last N)
- Fetch latest N interactions (N default 8, clamped to 5..10).
- Build numeric series:
  - accuracy: {0,1}
  - response time (ms)
  - hints requested
- Run linear regression slope for each series.

Step 5: Hidden state estimation
- Compute latent estimates:
  - frustration_estimate in [0,1]
  - engagement_estimate in [0,1]
  - readiness_estimate in [0,1]
- Build mastery summary from bkt_skill_mastery.

Step 6: Persist latent snapshot
- Upsert into student_profile_state for the user.
- Save trends + latent values + mapping metadata.

Step 7: State retrieval
- /api/bkt/state now returns:
  - FastAPI state label/signals
  - hidden state snapshot from student_profile_state

====================================================================
4) BKT FORMULA USED
====================================================================

Given current mastery P(L):
- If correct:
  P(L|correct) = P(L)*(1-slip) / [P(L)*(1-slip) + (1-P(L))*guess]

- If incorrect:
  P(L|incorrect) = P(L)*slip / [P(L)*slip + (1-P(L))*(1-guess)]

Then learning transition:
- P(L_new_before_forget) = P(L|evidence) + (1 - P(L|evidence))*p_transit

Optional forgetting:
- P(L_new) = P(L_new_before_forget) * (1 - p_forget)

The final value is clamped to [0,1] and stored as p_mastery.

====================================================================
5) TREND REGRESSION DETAILS
====================================================================

For each metric series y over x = 0..n-1:
- slope = Cov(x,y) / Var(x)

Interpretation:
- Accuracy slope > 0 => improving correctness over recent window.
- Time slope > 0 => response time increasing (often cognitive load/friction).
- Hint slope > 0 => reliance on hints increasing.

Trend labels:
- rising / stable / declining based on slope thresholds.

====================================================================
6) OBSERVABLE -> LATENT MAPPING (RESEARCH ANGLE)
====================================================================

This is the core latent-state interpretation layer.

Observed logs:
- correctness
- response_time_ms
- hints_requested
- sentiment_score
- session_time_spent_ms
- BKT mastery (P(Know) by skill)

Mapped latent states:

1) Mastery (latent)
- Derived from average P(Know) in bkt_skill_mastery.
- High mastery indicates strong conceptual retention.

2) Frustration (latent)
- Increases when:
  - accuracy drops
  - hints increase
  - response time grows
  - sentiment turns negative

3) Engagement (latent)
- Increases when:
  - interaction density is high
  - meaningful session time exists
  - persistence/hint pattern indicates active effort

4) Readiness (latent)
- Combines:
  - mastery level
  - recent accuracy
  - engagement
  - inverse of frustration

Why latent:
- Students do not directly emit "I am ready" or "I am frustrated" as reliable numeric fields.
- These states are inferred from observable behavioral traces.
- This is the research-valid bridge: logs (observables) -> hidden cognition (latents).

====================================================================
7) WHEN RECOMPUTATION HAPPENS
====================================================================

Recomputation is triggered after new interactions are persisted:
- Observation log/batch/hint routes
- Chat user/assistant event writes
- Direct BKT skill update endpoint also triggers profile-state refresh

This keeps student_profile_state near-real-time.

====================================================================
8) API/CONTROLLER IMPACTED
====================================================================

- backend_express/controllers/observationsController.js
  - persists student_interactions
  - triggers BKT/trend hidden-state processing

- backend_express/controllers/chatController.js
  - logs chat interactions into student_interactions
  - triggers hidden-state recomputation

- backend_express/controllers/bktController.js
  - update endpoint now refreshes profile state
  - state endpoint now includes hidden state snapshot

- backend_express/services/cognitiveStateService.js
  - central BKT + trend + latent computation logic

- backend_express/model/StudentProfileState.js
  - model for student_profile_state table

====================================================================
9) QUICK VALIDATION CHECKLIST
====================================================================

1. Submit interaction with correctness + contentId.
   Expected:
   - bkt_skill_mastery.p_mastery changes.

2. Submit 5..10 interactions with varied accuracy/time/hints.
   Expected:
   - student_profile_state trend slopes populated.

3. Hit /api/bkt/state.
   Expected:
   - hiddenState object with mastery/frustration/engagement/readiness and slopes.

4. Check DB tables:
   - interaction_logs receives raw logs.
   - student_interactions receives structured events.
   - student_profile_state updated with latest latent snapshot.

====================================================================
10) CONCLUSION
====================================================================

The system now performs cognitive understanding as a layered inference pipeline:
observables (interaction logs + BKT evidence) -> trend analysis -> latent state estimation.

This is suitable for research narratives around latent learner modeling, because it
explicitly documents and persists the mapping from behavioral traces to hidden states.
